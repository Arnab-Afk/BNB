## Contract Overview

| Contract | Purpose |
|----------|---------|
| `GhostPaymaster.sol` | ERC-4337 Paymaster. Sponsors BNB gas for users who provide a valid ZK proof from the privacy pool. |
| `GhostPool.sol` | Privacy Pool. Accepts stablecoin deposits, stores Poseidon commitments in a Merkle tree, and tracks spent nullifiers. |
| `Groth16Verifier.sol` | Auto-generated verifier. Performs on-chain Groth16 proof verification for `merkle_proof.circom`. |
| `PoseidonHasher.sol` | Wrapper around the Poseidon hash function optimised for Solidity (ZK-friendly, cheaper than keccak for ZK work). |
| `interfaces/IPaymaster.sol` | ERC-4337 `IPaymaster` interface (from the official EIP-4337 spec). |
| `interfaces/IGhostPool.sol` | Internal interface for Paymaster ↔ Pool communication. |

```
1. PoseidonHasher.sol          (no dependencies)
        ↓
2. Groth16Verifier.sol         (no dependencies)
```

## Contract Reference

### `GhostPaymaster.sol`

Inherits from OpenZeppelin's `BasePaymaster` (ERC-4337). This is the core contract that sponsors BNB gas for users who present a valid Zero-Knowledge proof.

#### Constructor

```solidity
constructor(
    IEntryPoint _entryPoint,    // Canonical ERC-4337 EntryPoint
    IGhostPool _ghostPool,      // Deployed GhostPool contract
    IGroth16Verifier _verifier  // Deployed Groth16Verifier contract
)
```

#### Key Functions

```solidity
/// @notice Called by EntryPoint to validate whether this Paymaster
///         will sponsor a given UserOperation.
/// @dev    Decodes the ZK proof from paymasterAndData, verifies it
///         on-chain, checks the Merkle root, and checks the nullifier.
/// @return context  ABI-encoded nullifier hash (passed to postOp)
/// @return validationData  0 = valid, 1 = invalid (SIG_VALIDATION_FAILED)
function validatePaymasterUserOp(
    UserOperation calldata userOp,
    bytes32 userOpHash,
    uint256 maxCost
) external override returns (bytes memory context, uint256 validationData);
```

```solidity
/// @notice Called by EntryPoint after the UserOperation executes.
/// @dev    Marks the nullifier as spent and deducts the USDC fee
///         from the pool balance to reimburse the Paymaster.
function postOp(
    PostOpMode mode,
    bytes calldata context,
    uint256 actualGasCost
) external override;
```

```solidity
/// @notice Owner can stake BNB into the EntryPoint to allow gas sponsorship.
function addStake(uint32 unstakeDelaySec) external payable onlyOwner;

/// @notice Owner can withdraw staked BNB (after unstake delay).
function withdrawStake(address payable withdrawAddress) external onlyOwner;
```

#### `paymasterAndData` Encoding

The frontend and backend must encode the ZK proof into `paymasterAndData` as follows:

```
paymasterAndData = abi.encodePacked(
    address paymasterAddress,       // 20 bytes
    uint48  validUntil,             // 6 bytes  (unix timestamp)
    uint48  validAfter,             // 6 bytes  (unix timestamp)
    bytes   encodedZKProof          // variable
)

encodedZKProof = abi.encode(
    uint256[2] pi_a,
    uint256[2][2] pi_b,
    uint256[2] pi_c,
    uint256[3] publicSignals        // [merkleRoot, nullifierHash, recipient]
)
```

#### Events

```solidity
event GasSponsored(
    address indexed sender,
    bytes32 indexed nullifierHash,
    uint256 gasCost
);

event NullifierSpent(bytes32 indexed nullifierHash);
```

### `GhostPool.sol`

The privacy pool where users deposit stablecoins and receive a cryptographic commitment. The pool maintains an incremental Poseidon Merkle tree of all commitments.

#### Constructor

```solidity
constructor(
    IPoseidonHasher _poseidon,  // Deployed PoseidonHasher
    uint32 _levels,             // Merkle tree depth (e.g. 20)
    IERC20 _usdc,               // USDC token address
    IERC20 _usdt                // USDT token address
)
```

#### Key Functions

```solidity
/// @notice Deposit stablecoins into the pool.
/// @dev    Commitment = Poseidon(secret, nullifier), generated client-side.
///         The contract NEVER sees secret or nullifier directly.
/// @param commitment   Poseidon hash of (secret, nullifier)
/// @param amount       Token amount (in token's native decimals)
/// @param token        Address of USDC or USDT
function deposit(
    bytes32 commitment,
    uint256 amount,
    address token
) external nonReentrant;
```

```solidity
/// @notice Check whether a given Merkle root was ever the canonical root.
/// @dev    Supports historical roots (last ROOT_HISTORY_SIZE roots stored).
///         This allows proofs generated slightly before a new deposit to
///         still be valid, preventing race conditions.
function isKnownRoot(bytes32 root) external view returns (bool);
```

```solidity
/// @notice Returns the current (latest) Merkle root.
function getLastRoot() external view returns (bytes32);
```

```solidity
/// @notice Called by GhostPaymaster.postOp() to deduct relay fee.
/// @dev    onlyPaymaster modifier — restricted to the GhostPaymaster address.
function deductFee(uint256 amount, address token) external onlyPaymaster;
```

#### Events

```solidity
event Deposit(
    bytes32 indexed commitment,
    uint32  leafIndex,
    uint256 amount,
    address token,
    uint256 timestamp
);
```

#### Merkle Tree Details

| Property | Value |
|----------|-------|
| Hash function | Poseidon (2-input) |
| Tree depth | 20 (configurable at deploy) |
| Max leaves | 2²⁰ = 1,048,576 deposits |
| Root history | Last 30 roots stored |
| Zero value | `keccak256("ghostpaymaster")` |

### `Groth16Verifier.sol`

> ⚠️ **Do not edit this file manually.** It is auto-generated by `snarkjs` from the compiled ZK circuit artifacts.

```bash
# Re-generate after circuit changes
npm run generate:verifier
# Internally runs:
# snarkjs zkey export solidityverifier merkle_proof_final.zkey Groth16Verifier.sol
```

#### Interface

```solidity
/// @notice Verify a Groth16 proof against public signals.
/// @return bool  true if the proof is valid, false otherwise.
function verifyProof(
    uint[2]    calldata _pA,
    uint[2][2] calldata _pB,
    uint[2]    calldata _pC,
    uint[3]    calldata _pubSignals   // [merkleRoot, nullifierHash, recipient]
) external view returns (bool);
```

**Public Signals layout:**

| Index | Signal | Description |
|-------|--------|-------------|
| `[0]` | `merkle_root` | Root of the Merkle tree at proof generation time |
| `[1]` | `nullifier_hash` | Poseidon(nullifier) — uniquely identifies this spend |
| `[2]` | `recipient` | Address of the UserOperation sender (binds proof to user) |

---

### `PoseidonHasher.sol`

A thin Solidity wrapper around the Poseidon permutation, precompiled as an assembly gadget. Used by `GhostPool` to hash pairs of Merkle tree nodes.

```solidity
/// @notice Compute Poseidon hash of two field elements.
function poseidon(bytes32 left, bytes32 right) external pure returns (bytes32);
```

> The Poseidon assembly is sourced from the [iden3/circomlibjs](https://github.com/iden3/circomlibjs) implementation and is optimised for the BN254 curve used by Groth16.

## ERC-4337 Flow

```
User (fresh wallet, 0 BNB)
  │
  │  Signs UserOperation:
  │  {
  │    sender:             <fresh wallet address>,
  │    callData:           <encoded function call>,
  │    paymasterAndData:   <GhostPaymaster addr> + <ZK proof>
  │    signature:          <ECDSA sig from fresh wallet>
  │  }
  │
  ▼
Backend Relayer  →  Pimlico Bundler
                          │
                          │  eth_sendUserOperation
                          ▼
                    EntryPoint.handleOps()
                          │
          ┌───────────────┴───────────────────┐
          │                                   │
          ▼                                   ▼
  GhostPaymaster                        Smart Account
  .validatePaymasterUserOp()            (user's wallet)
  │                                     .validateUserOp()
  ├─ Decode ZK proof
  ├─ Groth16Verifier.verifyProof() ✅
  ├─ GhostPool.isKnownRoot() ✅
  ├─ nullifiers[hash] == false ✅
  └─ return (context, 0)  →  APPROVED
          │
          │  EntryPoint pays gas from Paymaster's stake
          │
          ▼
  User's callData executes  ✅
          │
          ▼
  GhostPaymaster.postOp()
  ├─ nullifiers[nullifierHash] = true  (prevent replay)
  └─ GhostPool.deductFee(gasCost, USDC)
```

## ZK Proof Integration

### What the Contract Verifies

When `validatePaymasterUserOp` is called, it verifies **three things** from the proof's public signals:

```
1. merkle_root    → GhostPool.isKnownRoot(root) must return true
                    (The root the user proved against is recognized)

2. nullifier_hash → nullifiers[hash] must be false
                    (This proof hasn't been used before)

3. recipient      → must equal userOp.sender
                    (The proof is bound to THIS user operation specifically,
                     preventing a relayer from stealing the proof)
```

### Why `recipient` Binding Matters

Without binding the proof to the `userOp.sender`:
```
❌ Relayer could steal your ZK proof and submit their own UserOp
   using your proof → your USDC balance drained, their transaction sponsored.
```

With recipient binding:
```
✅ The proof is cryptographically tied to the sender address.
   Reusing it for a different address makes the proof invalid.
```

## Security Considerations

| Risk | Mitigation |
|------|------------|
| **Nullifier replay** | `nullifiers` mapping in GhostPaymaster; set to `true` atomically in `postOp` |
| **Fake Merkle root** | Root checked against `GhostPool.isKnownRoot()` — only canonical roots accepted |
| **Proof front-running** | Proof is bound to `recipient = userOp.sender`; unusable by anyone else |
| **Reentrancy in Pool** | `nonReentrant` on `deposit()` and `deductFee()` |
| **Stale root race condition** | Last 30 roots stored; proof generated just before a new deposit still valid |
| **Integer overflow** | Solidity `^0.8.24` has built-in overflow protection |
| **Paymaster insolvency** | `addStake` balance monitored by backend; auto-refill bot planned |
| **Trusted setup (ZK)** | Groth16 ceremony must be multi-party (MPC) for production |
| **Malicious token (Pool)** | Only whitelisted USDC/USDT accepted via `onlyAllowedToken` modifier |

## Gas Estimates

| Operation | Estimated Gas | BNB Cost (@ 5 Gwei) |
|-----------|:------------:|:-----------------:|
| `GhostPool.deposit()` | ~180,000 | ~0.0009 BNB |
| `GhostPaymaster.validatePaymasterUserOp()` | ~280,000 | ~0.0014 BNB |
| — of which: Groth16 `verifyProof()` | ~220,000 | ~0.0011 BNB |
| `GhostPaymaster.postOp()` | ~40,000 | ~0.0002 BNB |
| Full UserOperation (end-to-end) | ~420,000 | ~0.0021 BNB |

> ⚠️ On-chain Groth16 verification is the dominant gas cost (~220k gas). This is inherent to all Groth16-based ZK systems on EVM. Optimizations (e.g. Plonk verifier, precompiled BN254 calls) can reduce this in Phase 2.
